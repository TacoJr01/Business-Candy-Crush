## 1. What Parts 1 + 2 produced

**Part 1 (Rust, `src/business_candy_crush/`):** inverted TF-IDF index over S2+S3,
multi-channel top-k blocking. Metrics on the 220,441-entity train holdout
(`fnv1a64(id) % 10 == 0`): pair recall 0.9687, oracle F0.5 ceiling 0.9891,
~42.3 candidates/S1. Baseline score-threshold matcher: **F0.5 = 0.6892** (tau 2.28).

**Part 2 (Python, `src/matching/part2/`):** LightGBM over 44 features per candidate
pair; 5-fold by entity (fit/early-stop/calibration); global threshold tuned for macro
F0.5 on the calibration fold. Smoke test (5k entities) gave **F0.5 0.929 vs 0.705** for
the naive baseline on the same rows. Final full-val numbers: see
`work/part2/train_report.txt` (included in `part2_outputs.zip`) — should be a very
large lift over 0.689; sanity-check it when you open the report.

Key files (in `part2_outputs.zip`, not on GitHub — sizes):

| file | what |
| --- | --- |
| `output/matching_results.tsv` | **the submission file** (1,732,544 rows, one per test S1) |
| `output/candidate_pairs.tsv` | blocking candidates as submitted (~950 MB) |
| `work/part2/model.txt` | the trained LightGBM booster (small; also committed to git) |
| `work/part2/model_meta.json` | chosen tau, calib F0.5, val tag, baseline numbers |
| `work/part2/train_report.txt` | full holdout evaluation + threshold sweep |

Regenerating any of them takes the dataset + the two shell scripts; the model can be
retrained from scratch (`run_part2.sh`) because all caches live under `work/` (safe to
delete; each step is idempotent and re-caches).

## 4. Facts / caveats worth knowing

- **France is unseen in train.** Nothing in Part 2 branches on country (reporting only).
  Don't add any country logic when packaging.
- **Model licence/size constraint** applies to "final model": LightGBM is MIT, the
  booster is single-digit MB. Well within ≤8B params. (If someone asks "is an LLM
  required?" — no, it's not, and a GBDT is exactly the kind of submission this
  constraint anticipates.)
- **Fair play:** no external lookup/geocoding/APIs anywhere. Keep it that way.
- **Threshold semantics**: one global tau on model probability. Tuned on ~28k val
  entities that were NEVER used for fitting — the reported F0.5 should transfer.
  Re-tuning tau against leaderboard scores directly would be public-overfitting;
  don't.
- **Singletons**: ~5.6% of entities are empty-truth; the metric rewards empty
  predictions with a full 1.0. That's why F0.5 is much higher than pooled precision
  would suggest — don't "fix" the model if per-country P/R looks odd in the report.
- **Sizes**: val holdout = 9.3M candidate pairs; test = ~72M. predict_test takes
  roughly 45–60 min on a 12-core/16 GB laptop (parse 5 min, stores 8 min, inference
  ~30 min, write 3 min).
- **Caches**: everything under `work/part2/` (parses, stores, feature matrices). A
  store directory is only valid if its `_<tag>` suffix matches; deleting a cache dir
  forces a clean rebuild of that step only.
